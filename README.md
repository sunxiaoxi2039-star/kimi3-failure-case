> 一次「照猫画虎」失败的完整存档：目标、6 轮迭代、为什么没摸到精髓、以及教训。
> 案例代码见 `index.html`（最终版：樱花树可视化编辑器，可直接在浏览器打开）。

## 迭代实录（6 轮）

| 轮 | 做了什么 | 用户反馈 / 问题 |
|---|---|---|
| v1 | 低多边形山谷 + 9 棵小球树 + 四变体天光 | 「太抽象了，我想要那个樱花大树」 |
| v2 | 改成单棵递归分叉大树，树冠用点云 | 「出来的是球，原版能看到花瓣在树上」 |
| v3 | 花瓣 sprite 从圆点改成五瓣樱花剪影，加密到 8 万朵 | 「树叶好看，但要分布在整棵树上，要有风」 |
| v4 | 花沿枝干生长 + 枝梢垂花 + 风滚过整棵树 | 「树要居中看全貌，但叶子悬空了，看不到枝干」 |
| v5 | 主干加粗、树冠改壳层分布让骨架透出 | 形对了，但和原版质感差距仍大 |
| v6 | 加可视化编辑器（30+ 参数实时调） | —— 用户决定存档为失败案例 |

## 为什么判定为失败案例

1. **质感路线错误**：原版是**写实苔藓/花瓣材质 + 特写构图**（一根横伸巨枝占画面一角，配蝴蝶与卡片，高级感来自细节密度和留白）；我走的是**低多边形插画全景**，从第一版就选错了风格赛道，后面所有迭代都在错误的框架里修补。
2. **点云天花板**：用 `THREE.Points` + 自定义 sprite 模拟花朵，近看永远是「颗粒感」，达不到原版逐朵建模/实例化花瓣的体积感。8 万朵花不如人家 800 朵精致。
3. **构图失焦**：原版的精髓是「局部特写 + 大量留白」，我一直在做「整棵树全景」，宏大但平庸。
4. **迭代路径依赖**：v1 的框架（山谷+全景+变体）被一路沿用，每轮只是局部优化，没有在 v2 时推倒换构图。

## 教训（下次复刻这类作品时）

- **先拆原版的「视觉精髓三要素」再动手**：构图（特写 vs 全景）> 材质（写实 vs 插画）> 动态（风/粒子）。我在没有确认构图方向的情况下就写了 v1。
- **花瓣类自然物用实例化网格（InstancedMesh）而非点精灵**：每朵花一个带朝向的低模面片，才有阴影和体积。
- **先临摹构图再原创**：「做得更好」的前提是「先一样好」，方向错了，加法全是浪费。
- **2 轮没摸到精髓就该推倒重来**，而不是继续打补丁到 v6。

## 最终产物（不算全废的部分）

`index.html` —— 一个可玩的樱花树**可视化编辑器**：
- 递归分叉树 + 沿枝干生长的五瓣花（约 3 万朵）+ 6000 瓣落花
- 右侧调节面板：树位置/高矮粗细、树冠位置/大小/密度、13 个颜色、风力、雾/星/极光/萤火虫
- 四个氛围预设：樱吹雪 / 极光夜 / 森林晨雾 / 蓝调时刻
- 技术：Three.js r160（CDN importmap），零构建，单文件

作为「编辑器/玩具」它是完整的；作为「Sakura Sunset 复刻」它失败了。两回事。
